## Implemented in this batch

1. Removed the short-lived Gemini translation access ticket from the browser WebSocket URL. It is now sent as the first WebSocket message over the encrypted connection. The server rejects query credentials and accepts only allowed browser origins. Tickets are still single-use with Redis GetDel and short TTL.
2. Added periodic backend authorization checks for **both** listener and speaker while Gemini audio processing is active. When either participant loses call access, the AI stream terminates independently; the LiveKit call is not disconnected by this guard.
3. Corrected Gemini 3.5 Live Translate setup according to the **official Google Live Translation guide**: input/output transcription configuration belongs inside `generationConfig`, alongside `translationConfig`.
4. Made speaker identity validation exact: `u_<positive integer>`, rejecting suffixes or malformed IDs.
5. Categorized Gemini HTTP 429 and 401/403/setup failures into user-friendly quota/access errors without sending provider details or API keys to the browser.
6. Added backend regression tests for invalid ticket URLs, untrusted origins, model setup nesting, identity validation and safe AI errors.

Official API reference: https://ai.google.dev/gemini-api/docs/live-api/live-translate
