## Changes

- New JWT-authenticated `GET /api/conversations/memberships?limit=500&after=0` returns only the requesting user's currently authorized conversation IDs and an optional `nextAfter` cursor. Limit is bounded at 500 per page. Uses the existing `conversation_members(user_id,conversation_id)` index. No schema migration.
- React/PWA reconciles all pages when SSE reconnects, browser returns online, tab becomes visible, or at a 90-second interval. Failed/partial responses never revoke anything. Old/overlapping requests, logout, and concurrent group membership updates cannot overwrite newer membership state.
- After a complete authorized snapshot, removed conversations are excluded from cached state, pagination and in-flight list refreshes, and drafts/messages/group panes are cleared when applicable. A legitimate re-invite or creation restores visibility without keeping stale revocation tombstones.
- Existing `conversation.removed` events still provide immediate removal when online; the snapshot is a fallback when events were missed while offline.
