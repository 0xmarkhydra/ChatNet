## Scope and delivered code

1. `backend/cmd/chat/groups.go`
   - Group rename now repeats admin/owner authorization inside the SQL UPDATE.
   - Bulk member addition is transactional and locks actor membership; prevents partially completed batches if admin permission is concurrently revoked.
   - Owner/admin member removal is guarded in the DELETE statement against current actor and target roles; a stale request cannot remove a member after authorization changes.
   - Role promotion/demotion and ownership transfer are performed under actor/target row locks in a single transaction.
2. `backend/cmd/feed/main.go`, `backend/cmd/feed/manage.go`
   - Adding a comment requires current post visibility in the same INSERT statement.
   - Editing/deleting an existing comment requires current visibility in the same SQL statement, preventing edits after friendship/visibility is revoked.
   - Feed write endpoints `POST /api/posts`, `POST /api/posts/{id}/comments`, and `POST /api/feed/reports` use shared Redis-based per-account rate limiting.
3. `backend/cmd/feed/rate.go`
   - Reuses `internal/ratelimit.Limiter`; production feed now opens Redis using existing `redisx.Open` and `REDIS_URL`/`REDIS_ADDR` configuration.
   - Limits: 12 posts per 10 minutes, 30 comments per minute, 10 reports per hour.
   - HTTP 429 plus `Retry-After` when exceeded; HTTP 503 on Redis check failure (fail closed). Nil Redis is reserved for handler validation-only unit tests.
4. Real-infrastructure tests:
   - `backend/cmd/chat/groups_security_test.go`: three-user owner/admin/member permission operations, ownership transfer, kicked member cannot read group, single owner invariant.
   - `backend/cmd/feed/privacy_test.go`: three-user Friends/Private visibility, denied direct API access, denied interactions, loss of editing rights after unfriending.
   - `backend/cmd/feed/rate_test.go`: real Redis per-user rate-limit isolation and 429/Retry-After.
